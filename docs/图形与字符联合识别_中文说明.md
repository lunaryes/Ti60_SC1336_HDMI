# VF-Ti60F225 图形与数字、字母联合识别

## 本版保留与新增内容

基于已上板的 `0951267`（CCL＋Moore 图形识别），不是另做一个只有字符识别的替代工程。

保留：

- 原 Canny 算法、平滑三档、阈值调节、视频时序、UART 命令。
- 原图形 CCL、Moore 外轮廓、RDP 顶点及图形分类逻辑。
- 原高分辨率单字符 OCR，包括字体模板、门限和三次确认逻辑。

新增：

- 不依赖卡片的全画面字符连通域检测；每次最多显示四个新字符结果。
- 深色字/浅色背景和浅色字/深色背景分别分析。
- 每个候选自动裁紧、归一化，再匹配数字及大写英文字母。
- 新字符支路用“网格差异＋左右轮廓”联合评分，同时保留原始汉明距离不超过40的限制及不同类别间的分差要求。
- 中文类别标签，例如“三角形”“长方形”“数字4”“字母A”“未识别”。数字、英文字母本身保留原字符，不翻译成中文读音。

这里“中文显示”不等于“识别汉字”。当前字符类别仍为 `0～9、A～Z`；本版没有训练小写字母、汉字或任意手写体识别模型。

## 第三份参考资料如何去掉卡片前提

参考原作者项目：

https://people.ece.cornell.edu/land/courses/ece5760/FinalProjects/s2018/ac2369_de229_vg254/ac2369_de229_vg254/ac2369_de229_vg254/index.html

原项目先寻找卡片外轮廓、根据卡片角点旋转图像，再到卡片固定区域裁出字符，按网格前景占比匹配模板；其中旋转与字符识别部分在 ARM HPS 上运行。

我们没有卡片，也没有沿用其 ARM HPS 软件架构，因此采取以下调整：

1. 不检测卡片，不用卡片边框、固定角落或猜测的卡片中心定位字符。
2. 对现有灰度流进行自动对比度统计、双极性分割，直接寻找笔画连通域。
3. 用两遍八连通 CCL 和等价标签表，将每个候选的包围框分别提取。
4. 在候选框内按16×16网格统计属于该组件的前景占比，避免把旁边其它组件一起纳入。
5. 使用多字体模板、宽高比、网格重叠、左右轮廓和不同类别分差进行分类。
6. 同一字符和接近的位置连续两次出现才显示；空结果、溢出和超时清除新支路旧标签。

不照搬卡片旋转：没有已知卡片角点，就不能从外框直接确定字符朝向。本版优先处理基本正立的印刷体，不宣称完成大角度旋转或透视校正。旋转/透视严重时应拒识，而不是把未知目标硬判成字符。

## 针对开发板的实现

- Ti60F225，C4 时序模型；新逻辑全部使用既有 `clk_pixel` 和像素域复位。
- 原始有效画面1280×720；独立字符分析图320×180；每4×4像素统计占比，而不是只取一个像素。
- 使用片内 RAM 保存两位前景图、八位标签图、等价标签表及组件统计，不新增 DDR 仲裁或外部接口。
- 两遍 CCL 避免为字符另分配整帧洪泛队列，降低存储开销。
- 只读分支接在原中值灰度抽头；Canny 和图形分支的数据来源、控制、处理逻辑不变。
- 图像显示不等待字符引擎。引擎忙时跳过字符分析帧，不阻塞视频；因此字符更新速度低于视频刷新速度。
- 保留 KEY1 调三档平滑、KEY2 循环调阈值。它们仍控制 Canny，不强行兼作字符模式选择键。
- 保留串口速率460800、8N1及既有协议。`4F 00`关闭标注，`4F 01`开启标注，便于对比原始画面。
- 不更改摄像头、HDMI、DDR、PLL、引脚和外围约束文件。

## 使用方法

1. 先使用清晰、基本正立的黑色印刷体数字或大写字母；不需要卡片边框，也不要求文字在原橙色框内。
2. 字符高度建议80～300个原始图像像素，笔画清晰，字符之间留出至少约12个像素；避免极细字体。
3. 新支路候选高度范围为56～512像素，宽度不超过512像素；更小字符可由保留的原单字符支路补充，但不是全画面小字识别保证。
4. 保持静止约半秒，观察黄色字符框及“数字/字母”中文标签。
5. 同时放置三角形、圆或矩形，观察青色图形框和中文图形标签；几何类别与字符类别来自独立支路。
6. 橙色框仍是旧单字符通道的搜索范围，不能把它误认为新增全画面检测的边界。
7. 识别失败时先检查原灰度图是否失焦、过曝、倾斜、反光；Canny 阈值并不能代替字符分割门限。

## 必须知道的限制

- 不是通用场景文字检测器，不支持自动阅读一整段文字、任意手写体或汉字。
- 不同字体的 `0/O`、`1/I` 等可能外观相同。没有上下文时不能保证区分，分差不足就不显示类别。
- CCL 以相连笔画作为候选：粘连的相邻字符、断开的笔画、小写字母的点、大角度倾斜可能需要额外的组件合并/拆分。
- 每种极性最多255个临时标签、32个候选，每次最多显示四个确认结果；标签或时间超限时新字符支路拒识，原视频与图形识别继续运行。
- 同时保留旧通道会出现两种框：旧通道的框/特征预览与新字符框不是同一个算法结果。
- 保留现有算法和通过回归不等于保证所有实拍条件下准确率不变；最终应按同一摄像头位置、曝光、字号和测试图进行上板对照。

## 源码入口

- `character_frame_capture.v`：自动分割、深/浅色前景、4×4池化与完整帧捕获。
- `character_ccl_engine.v`：两遍CCL、组件统计、自动裁剪与网格采样。
- `character_matcher16.v`：独立的网格与左右轮廓联合分类，不替换旧分类器。
- `character_detection_top.v`：稳定确认、消隐期更新及过期清除。
- `vision_cn_font.v`、`vision_label_cn.v`：中文字体及类别组合。
- `character_overlay_cn.v`：字符框和中文标签。
- `shape_geometry_overlay.v`：只将原图形标签换成中文，图形分类逻辑保持原样。

仿真与最终硬件验证结果见随附验证记录；仿真字体样例不等于实拍准确率。
