# 字符识别重写说明（2026-10-21）

## 版本与适用范围

基于本机 `feature_shapes_chars_cn` 的 `8737b56100d0cbcfd714e2cab73ff09e3fa92ddb`，在独立本地分支 `fix_ocr_segmentation_tracking` 改写。按用户确认，发布目标为远端 `feature_shape_ocr_v1`，保留旧提交历史及本地修复分支。没有自动烧录。

面向 VF-Ti60F225、SC1336 摄像头、1280×720 视频。数字 0～9、大写 A～Z 是识别类别；不是任意字体、手写字、整页文字的通用 OCR。单个字符在输入图像中约需至少 40 像素高，最多同时输出 4 个字符；独立图形支路仍最多输出 4 个图形。超过容量时不保证选中用户希望的目标。

## 本次修改

1. **分区灰度阈值。** 在上一完整分析帧上统计 256×256 分区的明暗范围，局部阈值相对全局阈值限幅 ±48。低对比度分区回退全局阈值。参数在一帧内保持不变，改善明暗不均时笔画丢失。
2. **常规、细线双采样。** 每个 4×4 块同时保留 50% 占比和 25% 占比两种前景，正反极性共 4 位。细线支路负责保持斜笔画连通，常规支路保留较可靠的字形；分别分类后融合。两路同时确认但类别不同则拒识。
3. **CCL 容量与轮廓层级。** 临时标签从 255 个增加到 1023 个，每种极性最多分析 64 个候选。标签图、等价表、统计表、轮廓框表使用片内 RAM。反极性的内部孔洞不能作为另一个字符重复输出。
4. **保留完整对象内部笔画。** 裁剪框内不再只保留当前连通域而删除其它前景。原做法会把人脸的眼鼻嘴去掉，只留下类似 O 的外框。增加致密背景拒识，以及 0/O 的中心孔洞检查。负例通过不代表任意人脸都能保证拒识。
5. **重写模板竞争。** 采用 8 种字体（Arial、Consolas 及衬线、斜体变体），加入实心/描边两种原型、一像素对称容差和行轮廓误差。所有不同类别参与次优比较，不先用接受门限删掉竞争者。保留 a 的拒识样本，避免已经出现过的小写 a→8/O 错认；这不是完整小写字母支持。
6. **按位置跟踪。** 不再按 CCL 输出槽位确认。连续三次同类观察后显示，允许一次分析轮次漏检，类别变化立即撤销确认，长时间无新结果自动清除。快速移动超出关联范围仍会重新确认。
7. **统一显示。** 默认撤下旧固定 ROI OCR 支路及其橙框/字模预览，保留旧源码供历史测试。确认字符内的从属几何轮廓进行显示抑制，0/O/1/I 等歧义类别不用于压制图形。中文标签逐步排版，减少互相遮挡；不再用左上角一个字母概括多目标画面。

## 硬件约束

- 沿用 `clk_pixel`/`rstn_pixel`，不增加时钟、不更改 PLL、引脚、DDR3 或视频同步接口。
- KEY1 三档平滑、KEY2 阈值循环、UART 460800 8N1 协议保持原样。
- 分析忙时跳过分析帧，不阻塞摄像头或 HDMI。分析看灰度支路，显示视图不决定识别输入。
- 跟踪和字幕排版采用逐步状态机，避免把多目标匹配/布局串成像素时钟下的长组合路径。
- Canny、图形 CCL/Moore 核心源码未改。融合仅处理显示资格，不改变图形算法的原始输出。
- 字符分析看门狗为 1200 万周期；正常简单样例约 260～280 万周期，约 35～38 毫秒。三次确认及捕获节拍会增加显示延迟，并非每个视频帧都执行完整分类。

## 已知边界

- O/0、I/1 等形似类别不应靠强制优先级解决。有冲突或分数间隔不足时不显示；不能把拒识计作识别成功。
- 旋转、透视、失焦、反光、运动模糊、笔画粘连、过小字符仍可能造成漏检或错认。
- 不支持整页 26 个字母同时标注，也不承诺任意手写体、小写字母及真实场景的固定识别率。
- 几何核心保持原样，页面装饰边框仍可能被识别为图形；确认字符之外的曲线/多边形混淆没有在这次重写中全面重做。
- 模板方法仍有表达上限。若目标是任意场景 OCR，需要带真实摄像头样本的训练分类器、字符检测/分割及置信度标定，不能把本次改动说成已经具备这些能力。

## 测试与实机验收

完整结果和最终硬件资源、时序见同目录的验证记录/构建清单，不以中间构建或旧 bit 充当最终文件。

字符测试可运行：

```powershell
python sim/character_ccl/run_characters.py --extended --camera --stress --outline
```

需要 Pillow、Windows 字体和 Icarus；脚本工具路径默认对应本机 `F:\codex\tools\iverilog\bin`。

`--camera` 的三个裁片来自用户视频1约 1.2 秒的左侧灰度显示区，保存在 `sim/character_ccl/fixtures`。它们是手机拍屏后的诊断裁片，**不是原始摄像头帧，也不是完整视频回放的识别率**。右侧 Canny 画面没有伪装成原始灰度输入参与此项测试。

建议上板按下列顺序验收，保留失败画面，勿只拍成功瞬间：

1. 先显示单个清晰的 1、2、3、4、8、A、B、E、F、M，再显示 `AB42` 四个目标。
2. 固定同一图像，比较新旧 bit 的 Canny 主画面；UART `4F 00` 关闭标注，排除文字覆盖造成的“边缘变少”错觉。按现有串口文档恢复 `4F 01`。
3. 移动文字位置，短暂移出画面，核对是否重新确认、旧标签是否清除。
4. 分别试实心圆、带眼鼻嘴的脸、单个三角形，以及字母 A 和独立三角形并存；不能把内部孔洞的重复标注算成功。
5. 专门测试 O/0、I/1，记录拒识和错认，不能只记录“是否有字”。
6. 同一目标分别处于亮区/暗区、实心/描边字体，随后加入复杂背景。对比失败时的目标像素尺寸和聚焦情况。

本轮未自动烧录、未连接串口改变板上参数。新版本的实际提升必须以上述上板回归确认。
