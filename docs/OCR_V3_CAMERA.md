# 摄像头单字符识别 V3

## 改进依据

V2 没有在无有效候选的帧清除识别结果；一个曾经匹配的“4”可能在目标离开后一直保留。V2 实际为 8×8/64 位特征，最大距离18、类别间隔2；对自然场景的拒识不足。原12位计数左移比较还存在截断风险。

V3 为16×16/256位特征、288个模板（数字0–9及大写A–Z，各4种字体、2种笔画占用变体）。逐类取最佳字体，第二名必须来自另一个字符类别。最大汉明距离40/256、最小类别差10，同时检查前景重合和原始宽高比。

识别链读取灰度旁路：16级直方图稳健尾分位阈值、四角背景一致性/极性检测、连续像素候选定位、边框接触/密度/碎片检查、跨帧外接框稳定、16×16归一化、模板匹配、连续3帧确认。每个无效帧都会清除旧结果。

## 范围与显示

- 视频：1280×720；搜索区左上(320,120)，大小640×480。面积是V2的192×192的8.33倍。
- 橙框：搜索区。黄框：有效候选。绿框：稳定识别。
- 左上白色16×16图：实际采样字符；右侧绿色图：匹配模板。无效时显示空底。
- 左上第一行青色数字：3位Canny高阈值、1位平滑模式；如 `012 1`。
- 第二行黄色数字：3位OCR二值化阈值、1位拒识原因。
- 拒识码：0候选正常；1对比度/背景无效；2贴边；3尺寸/比例；4密度/碎片；5跨帧框不稳定。

目前范围内一次识别一个完整印刷字符，四角应留出均匀背景。范围变大不代表具备全场景文字定位或多字符分割能力。手写、任意字体、透视明显、字符重叠及自然物体仍可能拒识；模拟负例通过不等于真实人脸零误报。

初测建议字符高度至少40像素并保持静止；极小字的前景像素可能被直方图尾部分位视作噪点。`0/O`、`1/I`等外观近似时优先拒识，不能把拒识计作正确识别。

## Canny 与串口

图像核、控制器的阈值范围/步进、滤波、视图、AWB、HS/VS/DE延迟均沿用17日稳定版 `cdd6a8e`。OCR不反馈控制或阻塞视频流。默认高阈值12、平滑1、二值边缘分屏。重新烧录会丢失此前按键/串口的运行时设置。

460800 baud，8N1，HEX发送，无换行：

| 字节 | 功能 |
| --- | --- |
| `4F 00` | 关闭全部OCR标注，直接查看原视频流水线输出 |
| `4F 01` | 恢复OCR标注（默认） |
| `52` | 回读原7字节Canny/增益状态，协议长度不变 |
| `54 0C 53 01 56 00 4D 02` | 明确恢复阈值12、弱平滑、二值边缘、左右分屏 |

KEY1仍循环三档平滑，KEY2仍按1循环4…48；OCR二值化阈值独立自动估计。

## 上板检查

1. 固定摄像头、光照与同一测试图片，发送上面的恢复参数命令。
2. 交替发 `4F 00`/`4F 01`；普通像素的Canny边缘应保持一致，仅标注开关变化。
3. 在橙框内放完整黑字白纸“4”，避免其他物体进入框，观察黄框是否紧贴数字。
4. 黄框不出现先读拒识码；采样图不成“4”时，先检查定位/二值化，不能靠放宽匹配距离解决。
5. 成功后移走字符，绿色模板/标签必须消失；再用空白、脸或背景检查是否被拒绝。
6. 再换字符、大小、位置和白字黑底。记录正确、错误、拒识及总帧数，实拍效果须靠这些数据验证。

## 仿真

`sim/generate_ocr_font16.py --output-dir <目录>` 生成模板及灰度相机激励，需Pillow和本机Windows字体。生成的ROM已随源码提供，综合无需安装Pillow或字体。

`sim/tb_ocr_camera.v` 检查从灰度帧到字符结果以及移除后清除；`sim/tb_overlay_passthrough.v` 检查非标注像素逐位保持。原Canny回归及基线哈希见 `CANNY_BASELINE_AUDIT.md`。
