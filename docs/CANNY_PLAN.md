## 1. 目标

**效果目标**（相对现有 `sobel_edge`）：

| 指标 | 现状 Sobel | Canny 目标 |
| --- | --- | --- |
| 边缘宽度 | 2~3 像素 | **1 像素**（NMS） |
| 单边重复响应 | 有 | 无（NMS 去重） |
| 噪声假边 | 多（一个坏点成一圈假边） | 少（高斯 + 双阈值） |
| 断边 | 阈值一高就断 | 少（滞后连接） |
| 定位精度 | 一般 | 高（落在梯度极值处） |

**范围**：

- 做：**硬件近似版 Canny**（3x3 高斯 → Sobel 梯度 → 4 扇区方向量化 → NMS → 单遍双阈值滞后），全部在 `clk_pixel` 单域、行内流式处理。
- 不做：整帧迭代式严格滞后（需帧缓冲 / DDR3 多遍扫描）；5x5 高斯（先 3x3，效果不够再评估）。

**定位**：U5 可选扩展项之一。Canny 自带高斯平滑（替代中值去噪）和滞后连接（替代形态学补边），因此**与"中值 + 形态学"是二选一关系**，不叠加使用。

## 3. 算法方案（硬件近似版）

### 3.1 总体结构

```
p11..p33 ──► S1 高斯 3x3 ──► S2 加权和 ──► S3 Gx/Gy ──► S4 幅值+方向 ──┐
   (来自 pix_window_3x3)      （同 sobel S1）  （有符号11b）            │
                                                                      ▼
                                                    ┌── 梯度行缓存 ×2（同步读）
                                                    ▼
                              S5 NMS ◄── 3x3 梯度窗（mag + dir）
                                                    │
                                                    ▼
                              S6 双阈值 + 滞后（复用同一 3x3 窗）
                                                    │
                                                    ▼
                                            edge_o / mag_o
```

关键设计点：**NMS 和滞后判定复用同一个 3x3 梯度窗**，全流程只需要 2 个行缓存，不需要第三个窗口。

### 3.2 S1 高斯平滑（3x3）

核 `[1 2 1; 2 4 2; 1 2 1] / 16`，直接吃 `p11..p33`，`>>4` 用移位实现，无除法、无 DSP。

- 输出 `g22[7:0]`，宽度不增加。
- 高斯取代了中值滤波的去噪位置；若要两者并存，中值放在 Canny **之前**（可选，不在本方案范围）。

- **2026-10-17 实现为三档运行时模式**（`smooth_mode_i`，帧同步上升沿锁存，延迟不变）：
  `0` 标准高斯 `gsum>>4`；`1` 弱平滑 `(p22 + gaussian + 1)>>1`；`2` 完全旁路 `p22`。
  三档共用同一组流水寄存器，只多几个 MUX。默认 `1`（弱平滑），板上 K1 循环、串口 `'S'` 可写。

### 3.3 S2/S3 Sobel 梯度

与 `sobel.v` 的 S1/S2 完全同构：加权和（系数 2 用移位）→ 有符号相减。

- `Gx = (p13 + 2*p23 + p33) - (p11 + 2*p21 + p31)`（右列 − 左列）
- `Gy = (p31 + 2*p32 + p33) - (p11 + 2*p12 + p13)`（下行 − 上行）
- 范围 −1020 ~ +1020，`signed [10:0]`。

### 3.4 S4 幅值 + 方向量化

**幅值**：用精确的 `mag = |Gx| + |Gy|`（12 bit，0~2040），**不用** `max + min/2` 近似 —— 原因有二：

1. NMS 靠幅值比较定"谁是极大值"，近似会引入比较误差；
2. L1 在硬件上本来就只要一个加法器，比近似版**更省**（近似版要多一个比较器 + 两个 mux + 移位）。

**方向量化成 4 个扇区**（避免 `atan2` 和除法）：

| 判据 | 扇区 | NMS 比较的邻居 |
| --- | --- | --- |
| `\|Gy\| ≤ 0.414·\|Gx\|` | 0°（水平梯度） | `p21` / `p23` |
| `\|Gx\| ≤ 0.414·\|Gy\|` | 90°（垂直梯度） | `p12` / `p32` |
| 否则，`Gx` 与 `Gy` **同号** | 45°（梯度指向右下） | `p11` / `p33` |
| 否则，异号 | 135°（梯度指向右上） | `p13` / `p31` |

- `tan(22.5°) = 0.4142` 用 **106/256 = 0.41406** 近似（误差 0.04%），`106 = 64+32+8+2` → 4 次移位 + 3 次加法。
- 比较在整数域做：`(|Gy| << 8) ≤ 106·|Gx|`，约 19 bit 比较器，两个（0° 和 90° 各一个）。
- 符号只用于在两种对角情形间二选一，用 `Gx[10] == Gy[10]` 判断。
- 方向只参与"比较哪两个邻居"，不参与幅值，所以量化误差不影响幅值精度。

**方向编号 `dir[1:0]`**：`00`=0°、`01`=90°、`10`=45°、`11`=135°。

### 3.5 S5 梯度行缓存窗口

NMS 需要**梯度场**的 3x3 邻域（相邻行/列的幅值与方向），而 `pix_window_3x3` 提供的是灰度邻域，无法复用 → 需要新增 2 个梯度行缓存。

- 存储内容：`{mag[11:0], dir[1:0]}` = 14 bit/像素。**已定：先用 14 bit 精确版**（当前资源充足，见 §11）。
- 容量：2 × 1280 × 14 ≈ 35.8 kbit → 预计 4~8 块 `EFX_RAM10`（按 `pix_window` 实测折算：深度 1280 > 1024 需 2 块级联，宽度 14 > 10 需 2 块并联，每 bank 约 4 块）。
- **必须同步读**（见 §2.3）。
- 面积吃紧时的退化方案（后期不够再启用）：缓存 `mag >> 3`（0~2040 → 0~255，单调、无饱和平台）+ `dir` = 10 bit，每 bank 2 块。代价是 NMS 比较精度下降到 1/8 量化步长。

### 3.6 S6 非极大值抑制（NMS）

```
nms_keep = (mag >= mag_左邻) && (mag >= mag_右邻)      // 邻居由 dir 选
```

- **已定：保留平局**（`mag >= 两个邻居`）。理由：先用保留平局防止断边，看实际效果；代价是平坦处可能留下 2 像素宽的平台，后期若边缘偏粗再引入别的策略（例如按扇区区分严格/非严格，见 §11）。
- 抑制掉的像素 `mag` 置 0。

### 3.7 S7 双阈值 + 滞后（单遍近似）

```
strong = nms_keep && (mag8 >= thr_high_i)
weak   = nms_keep && (mag8 >= thr_low_i)
edge_o = strong || (weak && 8 邻域内存在 strong)
```

- **单遍近似**：只做一次 3x3 传播，不是真正的连通域递归。效果介于 Sobel 和 OpenCV Canny 之间，硬件上不需要帧缓冲。
- 邻域的 `strong` 用**未过 NMS 的原始幅值**判定（标准 FPGA 简化做法），这一点要在模块头注释里写明，避免后人误以为是严格 Canny。
- 更强的近似（流式反馈：把已处理的 `edge_o` 结果也纳入邻域判定）列为 M4 之后的候选，需要仔细处理扫描方向依赖。**2026-10-19 已实现，见本节末尾。**
- 滞后判定与 NMS 复用同一个 3x3 梯度窗，不额外增加行缓存。

**★★ M5 实测：这一版滞后的实际能力比"近似"还要弱，接近"把强边集膨胀 1 像素"。**
`testbench` 里的两条弱边用例（`faint_link` / `faint_iso`，`sim/canny_ref.py`）：

| 用例 | 弱边候选（过了 NMS、`mag8 ∈ [thr_low, thr_high)`） | 结果 |
| --- | --- | --- |
| `faint_link`（弱边接在强边上） | 20 个（其中 2 个贴强边） | 贴强边的 2 个被连上；同一列下面那条约 14 行的弱链**全丢** |
| `faint_iso`（孤立弱边） | 74 个（其中 2 个贴着一个孤立的强角点） | 72 个孤立弱边全部丢弃 ✓ |

原因：判据里的"8 邻域存在 strong"用的是**未过 NMS 的原始 `mag8`**，且**不递归**——所以弱边只能靠"碰巧紧贴强边"活下来，无法顺着链条传播。这是**已知退化**，不是 bug（回归断言按"贴强边 / 孤立"分类，对退化程度不敏感，见 §8）。
要真正实现 §1 目标里的"断边少"，需要按 §11 的候选做流式反馈版（把已输出的 `edge_o` 纳入邻域判定，沿扫描方向可递归）。**2026-10-19 已做：方向约束流式反馈，默认开，串口 `'L' 0` 可退回本节描述的单遍行为（见下）。**

**为什么这个退化在 M5 之前没被发现**：原来的默认阈值 40 太高（见 §3.8），整幅图上**几乎不存在**强弱边混排的情形——要么强、要么连梯度都没有，两条弱边用例在 40/20 下也就退化成"全丢"。阈值降到 16 之后弱带才真正有内容。

#### ★ 2026-10-19：流式反馈版已实现（方向约束、沿扫描方向递推）

`canny_edge` 增加 `link_en_i`（复位默认开）和 `link_o`，判决式变成：

```
link = link_gate && weak && !strong && !nb_strong
       && prev_row_tangent_edge && dir_compat
edge = strong || (weak && nb_strong) || link
```

- **切向邻居**由当前像素的 4 扇区方向选，只取**光栅序上已经处理过**的那一个：
  `dir=00`（梯度水平）→ 上；`01`（梯度垂直）→ 左；`10` → 右上；`11` → 左上。
  所以链是**沿扫描方向单向生长**的：竖直链从上往下、水平链从左往右。
  反方向（上/左）的链在同一帧里不会从种子往回长，这是单遍 rasterscan 的固有限制。
- **方向相容**：扇区按角度排成 `00(0°) → 10(45°) → 01(90°) → 11(135°)`，
  只允许相同或相邻扇区（环形差 0 或 3），90° 拐角拒绝。否则一条弱边会顺着
  完全不同朝向的噪声爬过去。
- **存储**：上一行判决后的 `{dir, edge}` → 2 个 `1280×3` ping-pong bank
  （当前行写 A、上一行读 B，下一行互换），约 4 块 EFX_RAM10；**没有帧缓存**。
  `edge` 是判决后的值，所以一行的结果会喂给下一行，链可以跨多行递推。
- **门控**：前 7 行不连接（行历史未灌满），列限制在 `3 .. IMG_W-3`（左右各留
  3 列，避开行首行尾的无效读）。`link_o` 只标"本来会被丢掉、因传播才留下"的像素；
  `mag_o/edge_o` 的时序不变，`LATENCY` 仍是 12。
- **运行时可关**：串口 `'L' <0|1>` 逐帧生效（`vsync` 上升沿锁存），关掉后
  `edge_o/link_o` 与加此功能前**逐位一致**；`view=2` 下绿色 = `link_o`。
- **验证**：`sim/canny_ref.py` 按同一行门控和逐行递推重算，`sim/run.sh` 第 1c 段
  对全部 13 个图样做 `link=1` 的逐像素比对（`edge` 和 `link` 都比），
  顶层 `tb_pipeline_top` 的 8 个帧时隙切 link 开/关并检查 view=2 的绿色。
  `faint_link` 的弱链在 `link=1` 时整条保留；`faint_iso` 的角点种子上仍会保留
  72 个弱候选中的 36 个（NMS 平局留下两条并行候选链，只有贴着种子的那条传播），
  参考模型与 RTL 逐位一致，所以这个用例按参考比对判，不按"整条保留"断言。

### 3.8 阈值域（重要）

内部判据统一用 **`mag8 = mag >> 3`**（0~2040 → 0~255，单调无饱和）。接口上 `thr_high_i` / `thr_low_i` 都是 8 bit，语义就是这个域。

- **与 `sobel_edge` 的 `thr_i` 不可直接混用**（sobel 是先饱和到 255 再比）。文档和寄存器默认值都要写清。
- **已定**：显示输出 `mag_o` 用**饱和版** `min(mag, 255)`，与现有 sobel 的视觉亮度一致；内部判据用 `mag8`。两者用途不同，模块头注释要说明。

#### ★★★ M5 事故：这个域的"有效量程"不是 0..255，而是 0..96 ★★★

`mag8 = mag >> 3` 是按理论满量程 2040 折算 0..255 的，但 **3×3 高斯把 Sobel 的 4A 阶跃响应压成了 3A**：

| 边界朝向 | 满对比度（ΔY = 255）时的 `mag` | `mag8` 上限 |
| --- | --- | --- |
| 横/竖 | 768 | **96** |
| 45°/135° | ~1120 | ~140 |

所以 8 bit 口按 "n/255" 理解会把对比度需求**系统性高估 2.7 倍**。精确标尺（`sim/color_probe.py` 用 RTL 同一套定点算子实算，含 `>>4` 截断，不是解析式估算）：

```
  mag8 ≈ 3·ΔY/8（横竖边）    ΔY = 边界两侧的灰度差 = 对比度

    thr        8    16    20    24    32    40    48
    需要ΔY≥   21    42    53    63    85   106   127
    占满幅     8%   16%   21%   25%   33%   42%   50%
```

- **原默认值 40 = 要求 42% 的对比度** ⟹ 这就是 M5 那次"红/紫/品红格子上的黑字完全没边"的**根因**。
  色卡上这几个颜色 AWB 后的 Y 是 99 / 90 / 105，对应 `mag8` = 37 / 33 / 39 —— 全部落在
  `[thr_low=20, thr_high=40)` 的**弱带**里，再叠加 §3.7 的滞后退化，就整条丢光了。
- **标定值：`thr_high = 12`、`thr_low = 6`**（顶层 `thr_i` 复位默认 12，映射 12/6；2026-10-15 上板扫出来的工作点，M5 时是 16/8）。12 对应 ΔY ≥ 32（13%），
  与作者原本想要的 `40/255 ≈ 15.7%` 意图一致，只是量纲改对了。
- **硬约束：`thr_high` 不要超过 48**（≈ 有效量程的一半），超过等于关掉边缘检测。
  `sim/canny_ref.py` 的 `main()` 开头有护栏，配成 > 48 直接判失败。
- **`mag8 = mag >> 3` 本身不改**：8 bit 口在 `thr=16` 处 1 个 LSB ≈ 2.7 个灰度级，分辨率够用；
  改成 `>>2` 或归一化到可达量程虽然让旋钮"读数即百分比"，但要动已冻结的 I-B 语义、参考模型和全部回归，
  收益不抵。**用这张标尺表代替改刻度。**
- **`mag_o` 不能用来调阈值**：它是 `min(mag,255)`，`mag8 > 32` 就饱和了（见 §3.8 上表：满对比度边 `mag`=768）。
  M5 为此加了 `mag8_o`（未饱和的 `mag >> 3`）与 `cls_o`（判决分类）两个观测口，
  并在 `image_pipeline_top` 里做了 4 种调试视图（见 §12 与 `INTERFACE.md` §6）。

## 4. 接口设计（I-B，冻结候选）

```verilog
module canny_edge #(
    parameter LATENCY = 0        // 实现后填写并冻结
)(
    input  wire        clk,
    input  wire        rst_n,

    input  wire        vsync_i,
    input  wire        de_i,
    input  wire [7:0]  p11, p12, p13,
    input  wire [7:0]  p21, p22, p23,
    input  wire [7:0]  p31, p32, p33,
    input  wire [7:0]  thr_high_i,
    input  wire [7:0]  thr_low_i,

    output reg         vsync_o,
    output reg         de_o,
    output reg  [7:0]  mag_o,
    output reg         edge_o
);
```

- 端口顺序符合 `INTERFACE.md` §2（`clk, rst_n, vsync_i, de_i, <data_in>, <ctrl_in>, vsync_o, de_o, <data_out>`）。
- 文件：`src/image/canny_edge.v`，模块名 `canny_edge`。
- **已定：与 `sobel_edge` 同插槽直接替换**，不引入 `generate` 二选一 —— 省下的资源留给后续模块。`sobel.v` 文件保留在仓库中，回归对照走分支/图样，不做同 bitstream 双实例。

## 5. 延迟预算

> 下表是方案阶段的**估算**（S1~S7 = 8 拍）。**实现后实际是 S1~S12 = 12 拍**
> （每一级组合逻辑都单独寄存：高斯的同步读/窗口、梯度场的同步读/窗口各占一级，
> 方案里把它们各算成 1 拍不够）。冻结值以 `INTERFACE.md` §4.5/§6 为准。

| 级 | 方案估算 | 实际（M3 冻结） |
| --- | --- | --- |
| S1 高斯 | 1 | 1 |
| S2/S3 高斯场行缓存（同步读）+ 窗口 | — | 2 |
| S4 加权和 / S5 Gx,Gy / S6 绝对值 | 2（合并计） | 3 |
| S7 幅值 + 定向乘法 | 1 | 1 |
| S8 方向量化 | （并入 S4） | 1 |
| S9/S10 梯度场行缓存（同步读）+ 窗口 | 2 | 2 |
| S11 NMS + 双阈值滞后 | 1 | 1 |
| S12 输出寄存 | 1 | 1 |
| **`canny_edge` 合计** | **8** | **12** |

对外总延迟：`rgb_to_gray 1 + pix_window 2 + canny 12 + image_mix 1 = 16` 拍（原 sobel 链路为 8 拍）。

`image_pipeline_top` 的 `ORIG_LAT` 相应是 **15**（= 1 + 2 + 12），`vsync/de` 对齐同步改；
`example_top` 里还有一处 `hsync` 延迟必须用**同一个数**（`IMG_LAT = 16`），否则 `rgb2dvi`
的 HS 与 DE 错位、HDMI 画面横移。原图路径是纯寄存器延迟，成本可控（15×24 = 360 FF），
但**必须与延迟推导注释一起改**，改完做旁路回归（`mode 0` 逐像素一致）。以上均已随 M4 完成。
（2026-10-17 接入 3×3 中值后总延迟变为 **19**：+1 中值 +2 后级窗口；`IMG_LAT`
随之改为 19，见 `INTERFACE.md` §6。）

## 7. 时序与流水划分

- 目标时钟 74.25 MHz（13.46 ns），每级组合深度控制在 **2 层 LUT + 一层比较/加法**以内。
- **反面教材**：本仓库 `feature_sobel_edge` 分支上的 `sobel_edge.v` 把整个 Sober 运算 + 对比度拉伸压进一拍，没有流水，时序余量被吃光。Canny 的组合链只会更长，**每一级都必须有寄存器**，`vsync/de` 逐级移位对齐（沿用 `sobel.v` 的做法）。
- 风险最高的两级是方向量化（移位加 + 19 bit 比较）和滞后（3x3 或树 + 双比较），必要时各拆成两级、LATENCY 相应增加。

## 8. 验证方案

1. **参考模型**：Python/MATLAB 实现同一套近似算法（4 扇区 + 单遍滞后），生成激励与期望输出，逐像素比对。注意参考模型必须用同样的近似，否则比对必然不一致。
2. **仿真用例**（新建 `sim/`，本分支此前没有）：

   | 用例 | 关注点 |
   | --- | --- |
   | 均匀场 | 不应产生任何边缘；高斯和 NMS 都不该引入假响应 |
   | 单像素坏点 | 高斯后应被削弱到阈值以下 |
   | 竖直/水平/斜 45°/斜 135° 直线 | NMS 后宽度必须是 1 像素，四个方向都要测 |
   | 1~2 像素细线 | 检查高斯是否把它抹平（这是 Canny 相对开关式中值的取舍点） |
   | 强弱边混合 | 滞后是否正确连接弱边、丢弃孤立弱响应 |
   | 首末行/末列 | 依赖 `pix_window_3x3` 的边缘复制，确认无异常 |
   | `de=0` 区段 | `mag_o`/`edge_o` 必须为 0，`vsync/de` 对齐正确 |

3. **板上验证**：静态图样 + 实景，与 sobel 对比"边缘连续性 / 假边 / 边缘宽度"，并确认旁路（mode 0）逐像素一致。

### 8.1 事后补的：这个验证方案当初漏了什么（M5 复盘）

原方案（上表 2）的 7 个用例全是"**实现对不对**"——参考模型与 DUT 共享同一组阈值常量，
逐点比对只能证明"RTL 和模型算的一样"，**结构上验证不了"阈值合不合适"**：两个一起标偏就
一起错，回归照样全绿。M5 那次"只有高对比度才出边"就是这么漏过去的。

补的两类（M5，见 `sim/canny_ref.py`）：

| 新增 | 内容 | 为什么能抓到标定问题 |
| --- | --- | --- |
| `pat_ladder` 图样 + 规格断言 | ΔY 阶梯（16/32/48/64/96/128/160/192 的竖条，背景 32） | 断言写成**与实现无关、与阈值具体取值无关**的规格：ΔY ≥ 128 的竖边界每一行都必须有 edge；ΔY ≤ 32 的竖边界不许连成线（最长连续 < 3 行）。阈值整体标偏，这两条立刻一条都不满足 |
| 弱边规格断言（替换原来的 `dut_weak > 0`） | 把"过了 NMS 的弱边候选"按 **8 邻域有没有强像素**分成两拨：贴强边的必须全连上、孤立的必须全丢掉 | 原来的断言要求"最终 edge 里的弱像素 > 0"，在 `faint_iso` 里其实只有 2 个像素同时满足两个条件，等于没测；现在是 20 / 74 个候选像素的定量检查 |
| `main()` 开头的阈值护栏 | `thr_high > 48` 直接判失败 | 把"可用量程只有 0..96"这条硬约束变成机器能把关的东西，防止下次又靠上板发现 |
| `sim/color_probe.py` | 独立的离线探针：AWB 削顶 → 灰度 → 高斯 → Sobel → mag8，输出标尺表 + 每个色块的判决 | 回答"这个颜色在 thr=N 下到底出不出边"，把 §3.8 的背表脚本化（标尺表就是它生成的） |
| `sim/tb_rgb_to_gray.v` | 颜色路径回归 | 集成回归灌的是 `{g,g,g}`，`(77+150+29)·g>>8 = g` 恒等 —— **颜色路径在集成回归里从未被激励过**（通道接反也测不出来） |
| `sim/tb_uart_cmd.v` + `sim/mut_uart.py` | 串口协议回归（真实参数 74.25 MHz/460800，18 个用例）+ 变异测试 | 串口是整个 M5 里**唯一"上板后没法用波形排查"**的新逻辑（排查手段只有串口本身，鸡生蛋），只能先在仿真里把协议咬死。`mut_uart.py` 用 3 个必死变异确认它不会假绿：命令用例的判据是几个寄存器，而寄存器会停在复位默认值上，整条接收通路失效时**照样"看起来在测"** |

#### 验证设施自身的三个坑（都不是 RTL 的问题，但都会把排查带偏）

1. **监视器从"半路"开始接收会整体错一位**。DUT 在 `'R'` 的停止位中点（≈9.5 位）就结束收字节并立即回包，
   而主机侧若等到"这一帧发完"（10 位 + 间隔）才开始收，回包的起始沿已经过去了 —— 接收端会从数据位
   中途上车，把 bit0 读成 bit1：实测 `thr=0x08` 读成 `0x84`、`view=0x03` 读成 `0x81`，**看起来像协议解析错了**。
   解法见 `tb_uart_cmd.v` 的 `send_cmd_nostop`（停止位只拉高电平、不等走完就返回）。
   上板选 USB-UART 时不会有这问题：那是常开的硬件接收端。（`INTERFACE.md` §7 已记。）
2. **`@(negedge tx)` 没有超时会挂死整条回归**。DUT 不回包时仿真永远等不到沿，进程 100% CPU 转下去，
   在 `run.sh` 里表现为"卡住不结束"，什么都不打印。现在的 `recv_byte` 按 clk 数拍采样（与 DUT 的
   分频比 161 对齐，**收发零漂移**）并带超时，超时判 FAIL 而不是挂死。
3. **`sim/build/` 是共享工作目录，两个 `run.sh` 不能同时跑**：激励、DUT 输出、编译产物同名，
   并发会互相覆盖，症状是 `$readmem file address beyond bounds`（大图样被小图样盖掉）——
   报错方向完全指错（像是激励生成器或 RTL 越界）。`run.sh` 已加锁目录（`mkdir` 原子锁）直接拒绝并发。

| 风险 | 对策 |

| 延迟从 8 变 12 影响顶层与文档 | M4 单独提交 + 旁路回归；同步更新 `INTERFACE.md` §5/§6、`ARCH.md` §2/§4 |
| 阈值域与 sobel 混淆导致调参错乱 | §3.8 明确写进模块头注释和接口文档 |
| **★ 阈值默认值标错，效果"只有高对比度才出边"**（M5 实际发生） | §3.8 的完整量程分析 + 标尺表；`sim/canny_ref.py` 的 `thr_high > 48` 护栏 + `pat_ladder` 规格断言；`sim/color_probe.py` 上板前先算；`mag8_o` 视图让阈值面在屏幕上直接可读 |
| **★ 单遍滞后退化成"强边膨胀 1 像素"，弱链仍断**（M5 实测，见 §3.7） | 2026-10-19 已加方向约束流式反馈（§3.7，默认开）：弱链沿切向逐行传播、`faint_link` 整条保留；`'L' 0` 仍可退回单遍行为用于对照。残留限制是链只能顺光栅方向单向生长、90° 拐角不连 |
| 参考模型与 DUT 共享阈值常量 ⟹ 回归**结构上**验证不了标定 | §8.1：新增 `pat_ladder` 的规格断言（与阈值取值无关）+ 独立离线探针 `sim/color_probe.py` |
| **色度感知缺失**：等亮度色边（不同色、同 Y）物理上无梯度，灰度链看不到 | **本分支不做**（需三通道各跑一遍梯度，资源 ×3）。当前口径：这类边检测不到是**正确行为**；`view_i=3`（Y 图）可以现场确认"是不是真的等亮度"，据此判断要不要立新任务 |
| **★ 采集端欠曝把阈值余量吃到 1 倍以下**（2026-10-15 上板实测） | 现象：品红/红/紫三格无响应，白/黄/青/绿正常；电脑屏调亮（≈80%）后**同一档阈值**下基本全部检出，再调亮又过曝（基线 AWB 削顶 `R≥161/B≥171` 把不同亮色压成同一个 Y → 块间边界消失，黑字仍清晰）。**量化**：那次实验的命令没生效，实际 `thr=32`（要求 ΔY ≥ 86，见 §10 下一行），而品红标称 ΔY = 105、红 99、紫 90 —— **余量只剩 1.2 / 1.15 / 1.05 倍**，采集端只要欠曝 20%（`k ≥ 0.82`）就三色全灭。反过来，"80% 亮度下全检出"要求 `k ≥ 0.82`，与"通常亮度下全灭"的 `k < 0.82` 正好夹住 —— **两条实测在同一个 k ≈ 0.8 上自洽**，不必引入新机制。同为 k = 0.8 时 `thr=16`（要求 43）给品红留 2 倍余量 ⟹ **标定本身没问题，是"不该存在的 32"×"0.8 的采集"两个 1.2~1.25 倍短板相乘**。**未分辨的混杂**：失效的三色既是"亮度只由 R、B 贡献"（品红 R+B、红 R、紫 R+B，都不含 G），又恰好是标称 ΔY 最低的三个，"色偏"与"整体欠曝"用现有数据分不开，要用 `view=3`（Y 图）读实测 Y 才能分开（白块也低 = 欠曝；白正常、品红塌陷 = 色偏）。**2026-10-15 第二次上板（命令格式改对后）的量化补充**：品红格的数字边在 `thr=16` 时**仍未过强阈值**、`thr=8` 时才过 ⟹ 品红的 `mag8 ∈ [8,16)`、实际 `ΔY ∈ [21,43)`，而标称是 `mag8=39`（`ΔY=105`）—— **只剩设计的 20%~40%**；同时白块"只比原图暗一小点"（≈0.8）。两者差 3 倍以上，**任何"整体欠曝/整体偏暗"都解释不了，只能是通道不平衡**：白块的 `Y` 有 59% 来自 G，G 保住就基本保住；品红/红/紫的 `Y` **全部**来自 R、B，R/B 一压就塌。与"整体偏绿 + 不鲜艳"的观察一致（R、B 弱 = 偏绿 + 不饱和）。**边界**：`mode 0`（原图）走的是**纯基线通路**，我们的模块只加延迟、改不了颜色 ⟹ 这个色偏 100% 在**摄像头 / 基线 AWB / 光源**，不是本流水线的 bug。**眼下可用**：`thr=8` 下所有色块都能检出，且盖镜头全黑（**噪声地板干净**）—— 可以先按 8 跑，但余量很薄，现场光照一变就没了。**对策**：①`thr` 设回 16（复位值本来就是 16）；②查采集曝光 —— `src/cmos_i2c/I2C_SC1336_1280720_Config.v` 的 `3e01=5d`/`3e02=80`/`3e08=1f` 是开机写死的**固定值，全工程没有 AE 环**，场景一暗没有任何补偿；`example_top.v` 的 AWB 增益 `×409/×384` 是**基线代码不是本次改的**（属集成负责人范围）；③若两条都动不了（demo 现场亮度不可控），才把 `thr` 默认值降到 8~12 —— **必须先盖镜头用 `view=1` 量噪声地板**（§3.8 的 ΔY≥22 判据） |
| **★ 判"通道性衰减 vs 整体欠曝"的天然对照对：标称并列、实测分家**（2026-10-15 第二次上板） | 现场色卡（已固化进 `sim/color_probe.py --card user`）上，**红 `(220,30,30)` 与深紫 `(110,30,200)` 的标称完全并列**：`Y` 都是 99、`mag8` 都是 37。但板上**深紫明显更难**（`thr=16` 只到弱边、`thr=8` 才过；view 3 里也比红更暗）。标称并列而实测分家，**不可能是整体曝光/等比缩水**（那会同比缩），只能是通道性的 —— 机制是 AWB 削顶：红的 `R=220 ≥ 161` **被削顶成 255**，它的 `Y` 里 **77/99 来自这条饱和通道**，上游 R 只要还 ≥ 100 就仍削到 255、咬不动；深紫的 `R=110 < 161` **不削顶**，`R'` 随上游 R 线性缩水（B 则是削顶的）。⟹ 被压的是 **R（和/或 B）**，与"整体偏绿 / 白物偏冷"一致。**以后标定时留着这一对做对照**，比看单块亮暗可靠得多。2026-10-15 第三次上板复现且加强：紫在中环、红在最外圈，而画面是"中心亮且清晰、边缘暗且模糊"——**空间梯度对紫有利**，可实测紫仍然比红难（`thr=16` 时红 90% 可见、紫只有下半部分），**逆着空间梯度的次序只能由通道性衰减解释**。方向进一步收窄到 **R**：若衰减的是 B，紫的 B 本来就削顶（α≥0.85 就仍钉在 255）、红的 B 只有 45，两者都不受影响；只有 R 被压时，红（R=220 削顶钉死）与紫（R=110 线性掉）才会分家。**白墙对照坐实**：在正常室内白灯下拍**远处的白墙**（人眼看是干净中性白、环境无异常），相机输出**发青** —— 中性白被渲染成青色就是 R 偏低的直接结果；贴近拍白物则整体过暗（无 AE，场景一暗就欠曝）。对策：`example_top.v` 的 AWB 增益已改成**运行时旋钮**（`'A'`/`'B'` 命令，见 §12.2 已实现段），对着白墙/白纸把 R 调回中性即可 | 
| **★ 用"自带亮度/清晰度梯度的画面"当上板判据会被带偏**（2026-10-15 第三次上板） | 现场例图本身就"**下亮上暗 + 中心清晰边缘模糊**"（相机贴近拍 LCD，边缘视角/暗角所致）。后果：同一颜色的 `mag8` 在画面上半和下半差一大截 → 表现为"某色只在下半部分可见"；`thr=8` 时"只有**中间对角线**上的黄/白格出现细线"= 中心分辨出的高频细节过了阈值。**这两条都不是阈值的性质，是靶面的空间梯度。** 判据：跨颜色比较"第几档 thr 出现"时，必须取**同一亮度、同一清晰度区域**的实例，否则会得出错误的"某色更难检出"。**建议**：上板判据尽量用**打印纸卡 + 均匀照明**，或把相机拉远、正对屏幕（别贴着拍）。本次实测的最佳工作点：**`thr=12`**（除紫最暗部与最暗灰外全部检出，且无多余细线）；`thr=8` 是这套画面的地板，再低就会把中心区的细线也收进来 |
| **★ 串口命令被当文本发送：空格 `0x20` 被当成参数字节吃掉**（2026-10-15 上板实测） | `T`/`V`/`M` 是**二进制**协议（命令字符 + 紧跟一个原始字节），不是 `T 16` 这种十进制文本。实测 `T 16` 按文本发出去 = `54 20 31 36`，参数位是**空格 0x20 = 32**，`1`/`6` 被当未知命令忽略 → `thr` 恒为 32，**整轮"阈值扫描"什么都没扫到**（回读 `20 00 03 0A` 就是这么来的）；`V 02` 同理变成 `0x20 & 3 = 0`，假彩图从未生效（屏幕一直是 view 0 的二值边缘图，"只有白边"是 view 0 的定义）。对策：字节表进 `INTERFACE.md` §7；**每发一条参数命令立刻 `R` 回读**；下一版给 `T`/`V`/`M` 加自动回显 + 十进制文本形态（§12.2）。**教训**：一个"参数没生效但不报错"的调试口，会让整轮上板实验的结论全部作废——实验数据必须带"设置已生效"的证据 |
