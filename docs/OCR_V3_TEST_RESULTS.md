# OCR V3 仿真测试记录

测试日期：2026-10-21。以下为 Icarus Verilog 的流式灰度帧仿真结果，不代表已经在摄像头实拍场景达到相同准确率。

## 测试输入与限制

模板包含 0–9、A–Z 共 36 类，每类使用 Arial、Arial Bold、Consolas、Consolas Bold 四种字体，各自采用 25%/40% 前景占用门限，共 288 个 16×16 模板。生成脚本在 128 字号下渲染字符，再按紧外接框归一化。RTL 使用逐类别最优分数比较，不把同类别的不同字体当作第二类别。

测试将 128×128 灰度小图嵌入完整的视频行、场时序中。数字 4 使用两种字体、40/64/96 三种字号、黑字白底及白字黑底；其他字符使用两种字体的 96 字号。每个成功测试还检查字符移出后，连续空白帧能够清除旧标签。

这些正例与 ROM 使用相同字体家族，因此属于受控合成测试，不能用于宣称任意字体、拍摄透视、失焦、摩尔纹或真实人脸的识别性能。模拟脸只是少量负例之一，并非真实人脸数据集。

## 已测结果

| 测试 | 实际结果 |
| --- | --- |
| 数字 4：Arial/Consolas × 40/64/96 字号 × 两极性 | 12/12 正确识别，移除后旧标签清除 |
| 空白白底、空白黑底、方框、模拟脸 | 4/4 拒识，没有误识为字符 |
| A/B/S/5/G/C 两字体、Consolas O/0/I、Arial/Consolas 1 | 17/17 正确识别，移除后旧标签清除 |
| Arial O | 拒识；候选有效，最佳距离 11、第二类别距离 12 |
| Arial 0 | 拒识；候选有效，最佳距离 8、第二类别距离 9 |
| Arial I，修复窄字前 | 拒识；外接框宽度小于原有 16 像素下限，reason=3 |
| 窄字修复后单独回归：Arial I + 原首四个数字 4 测试 | 5/5 正确识别，移除后旧标签清除 |
| 窄字修复后的最终完整 36 项、同一源码快照 | 严格 34/36 PASS；30 个正例正确，2 个正例拒识，4 个负例拒识，0 错类/误接受 |
| `iverilog -g2012` 相机测试编译 | PASS |
| `iverilog -g2005 -s simple_shape_ocr -t null` | PASS |
| 1280×720 视频、640×480 搜索区、每格 650 像素 | PASS；采样位图逐位等于预期，无溢出 |

第一次完整 36 项严格测试是 33 PASS、3 拒识、0 错类。之后单独修改窄字处理并完成 5 项回归；不能将两个代码快照的结果冒充一次新的完整测试。Arial O/0 的原始期望仍分别为 O/0，拒识在严格测试中仍为 FAIL；没有通过放宽类别差距门限掩盖失败。

随后已在窄字修复后的同一快照重新执行全部 36 项：30/32 个字符正例正确识别，Arial O/0 两项保守拒识；4/4 个负例拒识，无错类、无负例误接受。全部通过项同时验证了移除字符后的标签失效。严格返回码仍为 1，对应两个真实拒识的 FAIL，不能把该测试描述为“全部通过”。最终记录为生成目录下 `tests/ocr_camera_final.json`，包含完整输出及编译源文件 SHA256；该次仿真用 sampler、matcher、wrapper、ROM 的内容均与 Efinity 项目文件一致。

生产尺寸测试使用 1280×720 视频、640×480 搜索区，并将模板每格扩展为 25×26=650 像素，以检查 V2 曾出现的计数移位溢出。`tb_ocr_large_roi` 已通过，生成的 256 位采样图案逐位等于预期。

## 复现方法

需要 Python、Pillow 和 Icarus Verilog。脚本默认从 `C:/Windows/Fonts` 读取字体，可用 `--font-dir` 改为包含相应字体文件的目录。

```powershell
python sim/generate_ocr_font16.py --output-dir sim/build_ocr
python sim/run_ocr_camera.py --generated-dir sim/build_ocr --iverilog-dir F:/codex/tools/iverilog/bin
```

在仓库中脚本会自动使用 `Ti60F225_SC1336_HDMI_Display/src/recognition` 下的 RTL；在临时开发目录中也支持 `src`。测试程序和 JSON 报告写入生成目录的 `tests` 子目录，不向跟踪的 `sim` 根目录写入产物。`--work-dir` 可指定工程根目录，`--name` 可重复提供以运行部分用例。

```powershell
python sim/run_ocr_camera.py --generated-dir sim/build_ocr --name character_I_arial --name digit4_arial_40 --name digit4_arial_64 --result-name narrow_i_regression
```

JSON 同时保存严格 PASS/FAIL、实际正确/拒识/错类分类、仿真原始输出和参与编译的源码 SHA256。遇到允许保守拒识的模糊字符，脚本仍记录原本期望标签与非零严格测试返回码。

窄纯竖线有一个显式例外：当实拍字形宽度小于 16 像素且几乎为实心竖笔画时，实时 RTL 将其放大为满 16×16 位图，同时保留实际宽高比用于匹配。生成器仍保留原有 floor 分箱 ROM 数据；窄字源图可能产生空采样格，实时满位图可匹配粗体 I 模板。本次未改变 ROM 生成规范，避免让仿真与已经综合的模板数据不一致。

## 上板仍需验证

应分别观察原始灰度、二值化、字符外接框、归一化位图及最终类别，先用单个印刷字符和较均匀的背景测试。随后单独采集未参与模板生成的字体、不同距离和曝光的正例，以及真实人脸、手、背景物体等负例；分别统计误识和拒识。尤其需要确认搜索区扩大后复杂背景被拒绝、旧识别能及时清除，以及 Canny 旁路输出未受影响。
