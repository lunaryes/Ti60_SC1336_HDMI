# L2 验证报告 —— RTL 与 Python 参考模型逐像素比对

> 对应 `.github/PULL_REQUEST_TEMPLATE.md` 的 L2 要求：「与 Python 参考模型逐像素比对，附报告路径」。
> 本文件即该报告；机器生成的原始输出见 `sim/l2_report.txt`。
> 复跑：在仓库根目录执行 `sh sim/l2_verify.sh`（退出码 0 = 全部通过）。

## 1. 结论

| 项目 | 结果 |
| --- | --- |
| 覆盖 | `MODE = 0/1/2/3` × `THR = 40/100`，共 **8 组** |
| 每组的被测对象 | 两条独立实例：`EDGE_BINARY=1`（二值边缘图）、`EDGE_BINARY=0`（梯度幅值灰度图） |
| 判定区域 | 裁剪后可见区，**2640 点/实例**（图像 64×48，行 ∈ [2,45]、列 ∈ [2,61]） |
| 逐像素比对总量 | 2640 × 2 × 8 = **42 240 点** |
| 不符点数 | **0** |
| 结论 | **PASS** |

三条独立通道 + 一条内嵌通道全部对上：

1. **旁路原图**（mode 0 / mode 2 左半）：输出与源图**逐像素相等**（含固有 1 行垂直下移的字形对齐）。
2. **梯度幅值**（`EDGE_BINARY=0`）：`mag = |Gx|+|Gy|` 的**完整 8 bit 数值**逐像素相等，含饱和到 255 的路径。
3. **二值边缘**（`EDGE_BINARY=1`）：`mag > thr` 的 1 bit 判定在**两个不同阈值**下都逐像素相等。
4. **画中画内嵌图**（mode 3）：内嵌区逐像素等于「源图 2:1 抽取后的二值边缘图」，
   背景区逐像素等于原图。内嵌坐标映射按实现约定
   `(iy,ix) → 抽取样点 (min(iy+1,PH-1), min(ix+1,PW-1)) → 流位置 (2dy, 2dx)` 复算。

## 2. 方法

```text
sim/tb_l2_dump.v                       tools/l2_ref_model.py
    │                                        │
    │ 64×48 源图（上半平滑斜坡 + 下半伪随机）    │
    │ ├─► image_pipeline_top (EDGE_BINARY=1) ─┼─► sim/l2_out_bin.txt ─┐
    │ └─► image_pipeline_top (EDGE_BINARY=0) ─┼─► sim/l2_out_mag.txt ─┤
    └─► 源像素流 ────────────────────────────┴─► sim/l2_in.txt ──────┤
                                                                     ▼
                                              按 §INTERFACE 冻结公式独立重算，
                                              与 RTL 输出逐像素比对
```

**关键点：参考模型不读 RTL 代码。** `tools/l2_ref_model.py` 只实现
`docs/INTERFACE.md` 冻结的数学定义（`Gx/Gy`、`mag` 饱和、`edge = mag > thr`、
三种模式的合成规则），输入只有转储出来的源像素流。因此它对 RTL 是黑盒独立复算。

- **源图**：上半幅平滑斜坡（低梯度，考非饱和算术的精确性），下半幅确定性伪随机
  （高梯度，考饱和与阈值）。相邻行取值互不相同，避免行错位被图案掩盖。
- **帧处理**：每轮驱动 4 帧，取**最后一整帧**比对（第 1 帧行缓存尚未填满）。
- **几何约定**（与 `docs/INTERFACE.md` §6 一致）：输出第 m 行 = 图像第 (m−1) 行，
  输出第 k 列 = 图像第 k 列；窗口覆盖图像行 (m−2, m−1, m)、列 (k−1, k, k+1)。
- **mode 3 内嵌图**：右下 1/4 的内嵌像素 (iy, ix) 期望为「2:1 抽取后的二值边缘图」，
  按实现约定复算 —— 读抽取样点 `(min(iy+1,PH−1), min(ix+1,PW−1))`，
  其内容取自流位置 `(2·dy, 2·dx)` 的 `edge_rgb_i == 24'hFFFFFF`；
  背景区期望为原图。1 bit 缓冲使得两条实例（`EDGE_BINARY=1/0`）在内嵌区都输出二值。

## 3. 判定区域为什么是「行 ∈ [2,45]、列 ∈ [2,61]」

`FrameBoundCrop` 的判据是
`w_skip = (rc_w < SKIP_COLS) || (rc_w >= TOTAL_COLS - SKIP_COLS)`（行同理），
即 **每边各裁 2 行 2 列**。对本测试的 64×48 图，裁掉的就是行 {0,1,46,47} 与列 {0,1,62,63}。
剩余可见区正是「行 ∈ [2,45]、列 ∈ [2,61]」，与 3×3 窗口完全落在图内所需的
`m ∈ [2, H−1]`、`k ∈ [1, W−2]` 相比更保守，因此判定是安全的。

`docs/INTERFACE.md` §3 已冻结契约：**本模块不做任何边界特殊处理**，最外圈由裁剪兜底。

## 4. 裁剪区内的差异（已知、不可见）

比对同时统计了被裁掉区域的差异，仅作透明记录：

| 模式 | `EDGE_BINARY=1` 裁剪区不符 | `EDGE_BINARY=0` 裁剪区不符 | 差异所在列 |
| --- | --- | --- | --- |
| 0（原图） | 0 | 0 | 无 |
| 1（边缘图） | 0（THR=40）/ 2（THR=100） | 34 | 列 1 |
| 2（分屏） | 0 | 0 | 无 |
| 3（画中画） | 0 | 0 | 无 |

- 差异**全部落在列 1**，即 `FrameBoundCrop` 裁掉的最左第 2 列。
  根因是 `pix_window_3x3` 的 2 拍列流水在行首的固有偏移
  （详见 `docs/ARCH.md` §11.4），属「不做边界处理」的已知副作用。
- 之所以只有幅值实例暴露：该列 `mag` 数值确有偏差，但两个阈值下都判为「有边缘」，
  故二值实例大多一致；`THR=100` 时边缘恰好落在偏差量级上，才少数几处翻转。
- 这些点**在板上不可见**（被裁掉 2 列）。**可见区内 0 不符。**

## 5. 与 L1 的关系

| | L1 | L2 |
| --- | --- | --- |
| 脚本 | `sim/run.sh` → `sim/tb_image_pipeline.v` | `sim/l2_verify.sh` → `sim/tb_l2_dump.v` + `tools/l2_ref_model.py` |
| 期望值来源 | Verilog 内联 | **外部 Python 独立重算** |
| 图幅/内容 | 16×8，单一图案 | 64×48，平滑 + 伪随机 |
| 覆盖 | 288 项检查 | 8 组合 × 2 实例 × 2640 可见点 |
| 校验粒度 | 象限不变量 + 交叉点 | 逐像素数值 |

两者互补：L1 快、内联、便于回归；L2 独立、量大、可交报告。
