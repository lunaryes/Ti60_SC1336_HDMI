# DDR 应用帧存储

2026-10-22：以 `ddr_video_store.v` 替换旧 `axi4_ctrl` 接线。原本已存在的相机到 DDR 通道，现在保存完整、可选择的原始帧，再读取送入 ISP/Canny。

## 数据路径与容量

SC1336 RAW8 → 异步写 FIFO → DDR 完整帧 → 帧选择 → DDR 读取 → ISP/灰度/中值 → 运动自适应灰度 IIR（DDR 历史）→ 高斯/Sobel/NMS/连接/AA → HDMI。

- 每帧 1280×720×1 字节，921600 字节。每槽地址间隔 1 MiB，使用 DDR 前 16 MiB，共 16 槽。
- 写入槽无效；收到最后一个 AXI 写响应且像素计数正确后才发布为完整帧。最多保留 15 个完整帧；30 fps 时约半秒，属于短片段循环缓存。
- 保护当前显示、参考以及仍在读取的槽，避免读写同帧。显示帧切换时分时扫描元数据选择帧。
- 冻结、回放及对比模式在相机帧尾停止录入，保留缓存内容；恢复实时后继续循环录入。相机本身继续工作。
- FPGA 片内只保存短突发缓存及接口 FIFO，不再为串口图像诊断保存 ROI 或完整帧。

## 功能

| 模式 | 行为 |
| --- | --- |
| live | 显示最近完整帧，持续采集 |
| freeze | 停止录入，显示指定历史年龄的帧 |
| replay | 停止录入，在保留帧中按旧到新循环播放 |
| compare | 停止录入，左半画面来自 A、右半来自 B；各取原坐标，未缩放成两幅完整图 |
| difference | 停止录入，显示 RAW8 的绝对差×4并饱和到255，随后仍经过 ISP；不是灰度亮度差 |

年龄0为最近完整帧，1为前一源帧。指定年龄不存在时选择最接近的保留帧。回放间隔按 HDMI 显示帧计数，默认2；源帧率与显示帧率不一定相同。

## 抑制实时闪动：灰度递归 IIR

当前版替换了此前的 RAW8 两帧 FIR：`example_top` 将原 RAW 混合开关固定关闭，在中值之后、高斯/Sobel之前接入 `gray_temporal_iir`。NMS、阈值、连接及 AA 不变。

历史存储为16位容器中的 Q8.4（低12位有效），保留4位小数。递归公式为 `F = history + alpha × (current - history)`，有符号差值对称舍入，限制到0…255的Q8.4范围，显示时再舍入到8位。

| 判定 | 当前帧权重 alpha |
| --- | --- |
| 局部补偿残差≤2、水平/垂直梯度变化均≤4，绝对帧差≤24 | 1/2 |
| 局部补偿残差≤5、水平/垂直梯度变化均≤8，绝对帧差≤24 | 3/4 |
| 其他情况 | 1（直接用当前像素） |

局部 DC 为前一个完整16像素块的平均帧差，默认限制为正负8级灰度，行首继续使用最近块估计；每帧重新初始化。水平/垂直特征是时间残差相邻像素之差，等价于比较当前与历史的空间梯度变化；垂直方向使用一行缓存。它是低成本、因果的局部运动判断，没有运动矢量配准，参数仍需实际场景验证。

权重、门限和补偿上限现可用串口运行时配置，帧边界锁存；任意参数变化会使历史重新初始化。首次历史建立为原图拷贝，没有瞬间融合旧结果。

历史放在 DDR 的 `0x01000000` 和 `0x01200000` 两页，每页间隔2 MiB；每帧实际占1843200字节，不与前16 MiB的 RAW 槽重叠。独立异步 FIFO 和双主机读写仲裁连接现有 DDR。只有完整像素数正确且最后一个写响应完成后才发布历史页。

每个新且连续的源帧只递归一次；重复显示同一源帧时直接读取已提交滤波结果，不再次更新。首次帧、源帧跳转、AWB增益变化或历史失效时重新初始化；关闭滤波以及进入帧对比/差分模式时停用并清除有效历史。冻结同一源帧不会持续递归。

本工程 HDMI 帧同步为低有效。RAW 读控制器在同步上升沿开始选帧，因此 IIR 在该边沿后等待128像素时钟，再捕获源编号并预取历史，避免使用上一显示周期的编号。IIR 固定增加3个像素时钟，应用总延迟从23改为26，HS及原图支路同步对齐。

算法不能恢复白对白且原本没有梯度的轮廓；仍需评估细节损失、运动拖影及真实边缘变化率，融合比例不是画质改善率。

## 使用

Windows 安装了 pyserial 的 Python：

```powershell
python sim/video_control.py --port COM6 --mode live --tnr on
python sim/video_control.py --port COM6 --mode freeze --age 0
python sim/video_control.py --port COM6 --mode replay --replay-div 2
python sim/video_control.py --port COM6 --mode compare --age 0 --reference 1
python sim/video_control.py --port COM6 --mode difference --age 0 --reference 1
python sim/video_control.py --port COM6 --mode live --tnr off
```

脚本先检查固件协议标识，再设置参数并输出状态；不会下载固件或保存诊断图像。`--layout original|edge|split` 仍控制 ISP/Canny 的原图、边缘、左右显示；`--view gray|edge` 控制算法视图。

## 二进制串口协议

460800 baud、8N1。设置命令为 ASCII 命令码接一个原始数值字节，不是十进制字符串。

| 命令 | 参数/回复 |
| --- | --- |
| P | 0实时、1冻结、2回放、3左右帧对比、4绝对差 |
| N | bit0：灰度递归 IIR 开关，默认1 |
| J / K | A / B 的历史年龄，低4位，默认0/1 |
| O | 回放每帧持续的显示帧数，1…255；0钳制为1 |
| F | bit0：冻结1/实时0快捷方式 |
| Q | 8字节：`56 mode tnr ageA ageB divider 00 0A` |
| D | 8字节：`44 56 01 status[7:0] status[15:8] status[23:16] status[31:24] 0A` |
| R | 保持原有8字节图像设置回读 |

D 的 status：低16位为显示源 A 序号；18:16为生效模式；23:19为扫描时保留完整帧数；31:24为粘滞错误。错误bit0：不完整采集帧，bit1：AXI写响应错误，bit2：AXI读响应错误。状态通过请求/应答邮箱原子跨时钟域读取。源序号16位会回绕。

T/S/M/A/B/L 保持原有含义。Q 已改为应用配置回读，不再回复旧抗锯齿标识。顶层只保留 V=0边缘、V=3灰度；V=1/2按边缘处理。H 直方图与旧图像诊断链不接入综合，旧诊断脚本不能用于此固件。旧源码和离线测试可作为历史参考，不占板上资源。

## 验证范围

`bash sim/run_video_store.sh`：行为 FIFO/DDR 模型，带 AXI 背压和延迟写响应，检查冻结不被覆盖、历史选择、回放、对比、差分及逐输出字节的混合结果。模型不能替代真实 DDR/FIFO 时序验证。

`bash sim/run.sh`：原有 Canny、流水线、灰度、UART、按键和中值回归；直方图测试仅验证历史模块，应用顶层不例化它。上板后的视觉效果、显示连续性和运动拖影须独立验证。

## 灰度 IIR 验证方法

`bash sim/run_temporal_iir.sh` 使用两个并发 AXI 主机和带背压的 DDR 模型，逐像素核对独立定点参考，覆盖初始化、递归、重复帧、跳转重置、开关和移动边缘。

串口新增状态 `49` 和计数查询 `55`、`57`、`58`，详见 [UART_COMMAND_REFERENCE.md](UART_COMMAND_REFERENCE.md)。先发送 `49` 同时原子快照三组计数，再查询计数；缓存重复帧不会把最后一次计算的计数覆盖成零。

当前构建目录 `build_gray_iir/`；此前 `build_video_store/` 是 RAW FIR 历史版本，不再代表当前算法。

## 抗残影调参版（离线验证，未烧录）

针对运动残影，将默认权重由1/4、1/2、1改为1/2、3/4、1，并收紧运动门限、限制局部DC补偿。运动判断仍使用当前灰度与滤波历史的差值及其空间变化；没有新增上一原始灰度帧通道或运动配准。这是减轻拖影的第一轮参数和接口改进，不保证全部场景消除残影。

三时钟像素延迟、历史双缓冲、重复源帧只读复用保持原有设计。调参时，80位历史配置标识同时包含AWB增益和全部8项IIR参数，防止相同源编号错误复用旧参数结果。

合成低对比度移动边缘测试中，新旧参数使用相同初始历史和输入噪声；8个刚露出位置的灰度绝对误差总和由32降至4。该结果只属于此合成用例，不能替代实拍移动、停止和细字防闪验收。完整独立像素参考还覆盖旧权重选项、纯当前权重、参数变化时重置、DDR双主机及启动门控。
