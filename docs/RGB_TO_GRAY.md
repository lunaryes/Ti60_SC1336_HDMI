## 1. 灰度公式

使用常见定点亮度公式：

```text
Y = 0.299R + 0.587G + 0.114B
Y = (77*R + 150*G + 29*B) >> 8
```

系数 `77 + 150 + 29 = 256`，因此右移 8 位后保持 8 bit 亮度。输出为了兼容 HDMI RGB888，采用：

```text
gray_rgb = {Y, Y, Y}
```

**★ 上式的输入是 AWB 之后的 RGB**（`w_rgb_r/g/b`），而 AWB 会**削顶**：见 §4。
"对比度不够、边缘出不来"的问题**不要先怀疑这个公式**——它只是个加权和，
`(77+150+29)*g >> 8 = g` 在灰度输入下是恒等的；真正的变量是削顶后的取值。
（M5 事故的实际根因在 Canny 的阈值量程，见 `CANNY_PLAN.md` §3.8，与本节无关。）

## 4. AWB 的削顶（灰度链的上游，排查颜色问题必看）

`example_top.v` 的手动白平衡就是上面那两行 `assign`。**2026-10-15 起两个增益不再是写死的
常数，而是运行时可调寄存器**（`uart_cmd` 的 `'A'` / `'B'` 命令，1/64 定点，见 `INTERFACE.md` §7）：

```verilog
// gain_r / gain_b 来自 uart_cmd（复位值 112 / 96 = ×1.75 / ×1.5；112 是 2026-10-15 上板对白墙
// 二分调出的中性点，96 沿用老的 384/256。改前写死的 409/256 ≈ ×1.59 实测偏青）
wire [15:0] w_rgb_r_mult = w_rgb_pre_r * r_awb_gain;   // 增益 = gain_r/64
wire [15:0] w_rgb_b_mult = w_rgb_pre_b * b_awb_gain;
// 饱和：(R*gain) ≥ 256*64 = 16384 时给 255
assign w_rgb_r = (w_rgb_r_mult >= 16'd16384) ? 8'hFF : w_rgb_r_mult[15:6];
```

改成旋钮的原因：上板实测"**白墙在正常室内白灯下发青**"（2026-10-15）= 相机链路 R 通道偏低，
写死的 ×1.6 补不回来；而调这个系数要试好几轮，改常数反复综合太慢。

削顶阈值随增益变（`R ≥ 16384/gain_r`），复位增益下与老公式一致：

| 通道 | 公式 | 开始削顶的输入（gain_r=112 / gain_b=96 时） |
| --- | --- | --- |
| R | `R' = min((R*gain_r)>>6, 255)` | **R ≥ 147**（= 16384/112；gain_r 调大后阈值同比下降，旧 gain=102 时是 161） |
| G | `G' = G`（无增益） | 永不 |
| B | `B' = min((B*gain_b)>>6, 255)` | **B ≥ 171** |

对灰度链的两个后果：

1. **亮度整体抬高**：中灰 `(128,128,128)` → `(204,128,192)`，`Y` 从 128 变成 **158**。
   拿色卡对标称值时，务必用 `sim/color_probe.py --raw-rgb` 喂**未过 AWB 的原始值**，
   或直接看 `view_i = 3`（Y 图）读实际 Y。
2. **红/蓝通道的层次会被压平**：`R ≥ 161` 的所有红都被压成同一个 255，亮红和更亮的红在灰度链里
   变成同一个 `Y` —— 色块**内部**的纹理边界会消失。但"饱和色块 vs 黑字"这对端点不受影响
   （黑 `R=0 → R'=0`），所以 M5 那次"红格子没边"的主因不是它。
   **查顺序**：先用 `sim/color_probe.py` 算一遍 → 再上板用 `view 3` 量实际 ΔY → 最后才怀疑 AWB。

### 4.1 采集曝光/偏色对灰度链的影响（2026-10-15 上板实测）

灰度链的判据全是"两个像素的 `Y` 之差 ΔY"，所以**上游曝光直接决定下游还有多少余量**：
欠曝会把所有 ΔY **等比压小**（`Y ∝ 曝光`），而阈值是固定的 —— 相当于把对比度要求按比例放大。

上板实测到的一组现象与它的对应关系：

| 现象 | 解释 |
| --- | --- |
| 品红/红/紫三格无响应，白/黄/青/绿正常 | 标称 ΔY 最低的三个就是这三个（105 / 99 / 90，见 §1 标称表）；那轮实际阈值是 32（要求 ΔY ≥ 86），**余量只剩 1.2 / 1.15 / 1.05 倍**，采集端欠曝 20% 就全灭。**注意混杂**：这三色同时也是"亮度只由 R、B 贡献"的色（不含 G），所以"色偏"和"整体欠曝"用这一组数据**分不开** |
| 把电脑屏亮度调亮（≈80%）后，同一档阈值下基本都能检出 | 输入对比度回到标称附近（`k ≥ 0.82`）⟹ **阈值标定本身没错**，是输入端余量不够 |
| 调到最亮又过曝：棋盘格线条变模糊，黑字反而清楚 | 过曝把亮块推进 §4 的削顶区，不同亮色被压成同一个 `Y` → **块与块的边界**消失；而黑字与亮块这对端点不受削顶影响（黑 `R=0→R'=0`） |

两条实测夹在同一个 **k ≈ 0.8**（采集端只有标称的 8 成）上：通常亮度下三色灭要求 `k < 0.82`，
80% 亮度下全检出要求 `k ≥ 0.82`。**分辨"欠曝"还是"色偏"**要用 `view_i = 3`（Y 图）读各色块
实际 `Y`，与标称值（白 255 / 品红 105 / 灰 158，见 `sim/color_probe.py`）比：
**白块也低 = 整体欠曝；白块正常而品红塌陷 = 色偏**。灰格"只能隐约看到数字边"当初也是
同一条余量账（灰要三通道一起贡献 `Y`，是标称 ΔY = 158 里靠 §4 的 AWB 抬上来的）。

`src/cmos_i2c/I2C_SC1336_1280720_Config.v` 里 `3e01=0x5d`/`3e02=0x80`/`3e08=0x1f`
是开机写死的**固定**曝光/增益，全工程**没有自动曝光(AE)环**，场景一暗没有任何补偿 ——
"相机硬件偏暗"其实是这个固定配置，可调，代价是一次综合 + 一枚位流。

## 6. 时序与资源

- 时钟域：只使用 `clk_pixel`，不引入新跨时钟域。
- 输入格式：`rgb_i = {R[7:0], G[7:0], B[7:0]}`。
- 输出格式：`rgb_o = {Y[7:0], Y[7:0], Y[7:0]}`。
- 延迟：输出相对输入固定延迟 1 个 `clk_pixel`。
- 同步信号：`vs/hs/de` 同步寄存 1 拍，与 `rgb_o` 对齐。
- 资源：3 个常数乘法，可由综合器映射为 DSP 或移位加法逻辑。

 如果画面整体偏暗，可以把输出改为四舍五入：

```verilog
wire [7:0] y = (y_sum + 16'd128) >> 8;
```

4. 如果综合器对乘法资源比较敏感，可改成移位加法近似：

```verilog
Y = (R>>2) + (R>>5) + (G>>1) + (G>>4) + (B>>4) + (B>>5);
```
