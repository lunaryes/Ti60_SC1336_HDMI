# RFC 目录

本目录记录**会改变已冻结接口、或影响多人的设计决策**。

代码能回答"做了什么"，提交历史能回答"什么时候做的"，但都回答不了**"为什么不那样做"**。
RFC 补的就是这一段——它的价值在**备选方案被否决的理由**，而不是最终结论。

---

## 什么时候必须写 RFC

| 必须写 | 不必写 |
| --- | --- |
| 改变 `docs/INTERFACE.md` 里的冻结接口（端口、`LATENCY`、公式） | 模块内部实现细节调整 |
| 决定流水线的插入点、时钟域归属 | 新增一个 testbench |
| 模块命名 / 文件所有权冲突的处置 | 修一个已定位的 bug |
| 因资源不足而**降级**方案（如画质、位宽、抽取比） | 文档措辞修订 |
| 引入新的公共依赖或新顶层端口 | 纯格式化、注释完善 |

一句话判据：**如果这件事做错方向会让别人白干一天以上，就写 RFC。**

---

## 生命周期

```
Draft  ──讨论──▶  Accepted  ──实现──▶  Implemented
  │                    │
  │                    └──被推翻──▶  Superseded by #NNNN
  └──放弃──▶  Withdrawn
```

- **Draft**：作者写完并提交 Issue 讨论。此时可以自由改。
- **Accepted**：**2 人 approve** 后改状态。此后内容不得随意改写，要改就新开一篇。
- **Implemented**：对应代码已合并到目标分支，补上实现位置。
- **Superseded by #NNNN**：被新 RFC 取代。**不要删除旧文件**——历史本身就是资产，
  删掉它等于让后人重新踩一遍已经排除的坑。
- **Withdrawn**：讨论后放弃，同样保留，写明放弃理由。

## 命名与格式

- 文件名：`NNNN-短标题.md`，四位序号（从 `0001` 起）、连字符分隔、全小写英文
- 序号**一经分配不再回收**，即使该 RFC 被 Withdrawn
- 模板：[`0000-template.md`](0000-template.md)
- 新增后**必须**在下表登记

## 与文档的分工

| 载体 | 回答的问题 |
| --- | --- |
| `docs/INTERFACE.md` | **现在**的接口长什么样（契约，冻结） |
| `docs/ARCH.md` | **现在**的结构、资源、已知陷阱 |
| `docs/L2_VERIFY.md` | **现在**验证到什么程度、还没覆盖什么 |
| `rfc/` | **当时为什么**这么定，以及否掉了哪些方案 |

接口文档只写结论；理由写在 RFC 里，两边互相引用。
